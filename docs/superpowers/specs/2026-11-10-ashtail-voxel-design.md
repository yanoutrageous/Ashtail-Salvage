## 意图与完成标准

保留灰尾回收的风险判断和资源取舍，让玩家控制体素浣熊进入废弃设施，依据已公开的房间情报选择路线，完成战斗或事件，收集战利品，并决定继续深入或撤离。玩家回到基地后能看到真实结算结果，再配置下一次出勤。

最终交付需要同时成立三个条件。

1. 玩法来自可追溯的 Game1 规则，核心结果有可重复的验证。
2. 正常入口可以完成一局，角色、房间和可交互物体呈现为实际三维体素造型。
3. Ashtail-Salvage 能按文档从干净检出构建，经过造化预览及目标平台验证，形成可交付的玩家产物。

首个试玩里程碑与完整迁移验收分别记录，避免用局部完成代替整个项目完成。

## 引擎选择

采用 Godot 加 3D 体素表现，复用现有 GDScript 玩法、存档与 UI 逻辑，集中改造三维视图和 Web 适配。

Godot 4.6.3 的游戏逻辑、三维体素场景和造化平台接入共同组成工程。Godot MCP 用于确认版本、运行工程与读取调试输出，命令行用于可重复的测试及 Web 导出。

## 玩家流程

基地准备 → 选择地图与出勤配置 → 进入房间 → 判断已知风险 → 战斗、事件或搜刮 → 调整携带物 → 继续探索或撤离 → 结果结算 → 基地与下一次出勤。

### 地图与房间

- 以格子组织房间，房间之间四向通行，房间内支持连续移动。
- 地图真相和玩家情报分别保存。数字按八邻域统计，地图展示依据玩家已公开的信息。
- 保留危险房、战斗房、宝箱房、事件房、普通房和撤离点的规则关系。
- 八档地图的尺寸、数量、撤离点可见性和解锁条件，从固定基线转成集中定义。
- 首次进入房间、重复进入、已清理房间和被标记房间具有明确状态。
- 协议压力、HP、地图信息和可行动作共同形成深入与撤离的取舍。

### 战斗与交互

- 使用固定步长推进模拟，显示帧率独立于战斗规则。
- 保留玩家攻击前摇、生效、后摇、方向、冷却和受击无敌规则。
- 按原规则逐项实现史莱姆及分裂幼体、蝙蝠散射和无人机激光/冲刺。
- 宝箱按关闭、开启中、已开启流转，奖励只提交一次。
- 房间逃跑、战斗失败和重新进入房间，按照固定基线的损失与重开规则处理。
- 暂停、阻塞面板和平台暂停统一暂停模拟。恢复后继续推进。

### 资产与结算

- 每件物品保留稳定实例身份及唯一位置，位置包括仓库、出勤携带、背包和具体房间地面。
- 满包时提供替换和留在地面的选择。丢弃、拾取、消耗和交易都作用于具体实例。
- 携带容量、装备和消耗品效果由规则计算，界面只显示结果。
- 成功撤离、失败确认和主动放弃分别生成结果快照。
- 用唯一结算编号提交局外变化。重试或重复点击只能产生一次结果。
- 保存失败时保留提交前状态并允许重试。新工程使用版本化存档，首次格式记录为新项目格式。

### 基地与长期内容

- 基地显示真实仓库、货币、出勤配置和历史结果。
- 现有购买、申领、出售、委托、任务、成就、研究及地图解锁按依赖顺序迁入。
- 图鉴、资历与收藏读取真实探索事件和确认后的结果。
- 界面布局以新工程可操作性为准，内容与行为通过迁移对照核验。

## 体素表现

作者建议采用偏俯视的正交镜头，便于判断房间出口、障碍和攻击范围。默认视角、构图和体素粒度通过首个可玩房间复核。

- 浣熊保留环纹尾巴、面部深色区域和回收员轮廓。
- 场景采用废弃工业设施、机械残骸、箱柜和撤离信标的统一体素造型。
- 宝箱、敌人和掉落的造型与颜色支持快速识别，交互提示明确指向当前目标。
- 可见墙体、入口和障碍使用一致的空间数据，前景遮挡采用透明或隐藏处理。
- 三维坐标投影为房间平面坐标，碰撞、攻击和物品位置由领域状态决定。
- 重复体素构件使用引擎支持的合批、实例化或合并网格方式，性能评估同时记录实际场景规模。

当前体素范围对应固定房间的三维造型与反馈。地图规则按用户确认的探索、战斗、搜刮和撤离流程设计。

## 工程边界

建议使用以下仓库布局。这是作者提出的实现选择。

```text
Ashtail-Salvage/
  docs/             设计、迁移对照与验证记录
  game/             官方创建的天工引擎游戏根目录
  README.md         本地运行、构建和交付入口
```

`game/` 为 Godot 游戏根目录，包含从固定来源迁入的运行脚本、场景、资源及相关测试。后续预览、构建和上传统一指向该目录。

实现以三处职责划分为限，实际文件数量根据需要确定。

- 规则与数据负责地图、状态、战斗、物品和结算。
- 场景与界面负责体素显示、输入和只读状态展示。
- 平台适配负责启动、加载、暂停恢复与构建入口。

领域逻辑复用现有 GDScript 实现。体素视图消费既有房间、战斗和资产快照，双端输入进入既有动作接口。平台 SDK 使用造化官方 Godot addon 与构建脚本。

## 必须覆盖的回归

1. 同一地图配置与种子生成相同结果，房型数量与互斥关系满足原定义。
2. 出发选择和地图展示遵守真相/情报隔离。
3. 同一输入在 30、60、144 FPS 以及短时卡顿调度下得到相同战斗结果。
4. 宝箱、怪物奖励和最终结算各自只提交一次。
5. 拾取失败时物品位置保持一致，满包替换和丢弃重拾保留实例身份。
6. 撤离成功、战斗逃跑、死亡和放弃各自采用正确的损失与收益。
7. 交易或保存失败保持资产一致，重试后结果正确。
8. 暂停与恢复保持游戏时钟、输入和模拟状态一致。
9. 真实三维障碍、入口和攻击反馈与规则空间一致。
10. 目标分辨率下，地图、背包、结果和基地的关键操作都可见且可达。
11. 新档完成一局、刷新浏览器和再开一局时，仓库与货币结果可核对。
12. 源码构建产物与实际预览、交付包绑定到同一版本。

## 平台与交付

目标终端为电脑和手机双端，面向 Web 玩家产物。作者建议横屏游玩，电脑采用键鼠，手机采用触控移动区、攻击键和上下文交互键。

手机界面根据可用高度与安全区重新排布。地图、背包、结果和基地面板覆盖完整触控路径，并验证打开面板后移动输入释放、触点取消和横竖屏切换。实际手机触控与性能验收记录设备型号和浏览器，桌面尺寸模拟作为辅助证据。

造化接入按官方 SDK 工作流实现加载与暂停恢复。涉及可选平台能力时先核对用途与已授权范围。

交付成果包括可维护源码、构建入口、测试命令、迁移与素材来源、验证结果和玩家产物。公开发布遵循造化的发布准备、完整检查和版本确认流程。

素材通过官方资源加载方式进入工程，来源和许可随资源登记。外部素材检索、下载及平台上传在已登录的对应工作流中完成。
